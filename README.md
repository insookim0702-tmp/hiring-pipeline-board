# 채용 파이프라인 보드

지원자를 채용 단계별로 관리하는 칸반 보드. 서류검토 → 면접 → 처우협의 → 최종합격 / 불합격.
백엔드 없이 **자체 구현한 mock API**(지연 200~800ms, 실패 약 15%)로 동작한다.

- 설계 결정과 트레이드오프: [DECISIONS.md](./DECISIONS.md)
- AI 협업 프롬프트·검증 기록: [PROMPTS.md](./PROMPTS.md)

## 실행

```bash
npm install
npm run dev
```

| 명령 | 설명 |
| --- | --- |
| `npm run dev` | 개발 서버 (http://localhost:5173) |
| `npm run build` | 타입 체크 + 프로덕션 빌드 |
| `npm run preview` | 빌드 결과 미리보기 |
| `npm run test` | 테스트 94개 |
| `npm run lint` | ESLint (React Compiler 규칙 포함) |

## 스택

| 항목 | 선택 | 이유 |
| --- | --- | --- |
| 빌드 | Vite + React 19 + TypeScript | 백엔드가 없어 SSR이 필요 없다. strict 타입으로 상태 전이를 컴파일러에 맡긴다 |
| 상태 | `useReducer` + Context (라이브러리 없음) | 낙관적 업데이트·롤백·경쟁 상태가 이 과제의 평가 대상이라 직접 구현했다 |
| 스타일 | Tailwind CSS v4 | 밀도 높은 보드 UI를 빠르게. 디자인 시스템을 새로 만들 범위가 아니다 |
| 테스트 | Vitest + Testing Library | mock API의 지연·실패를 주입해 결정론적으로 검증한다 |
| 가상 스크롤 | `@tanstack/react-virtual` | 렌더링 유틸이며 상태 로직에는 관여하지 않는다 ([DECISIONS](./DECISIONS.md#5-가상-스크롤만-라이브러리를-썼다)) |

## mock API

`src/mocks/` 에 직접 구현했다. 네트워크 계층을 흉내내는 별도 라이브러리는 쓰지 않았다.

- **지연**: 모든 요청에 200~800ms
- **실패**: 약 15% 확률로 `NetworkError`. 실패는 **쓰기가 반영되기 전에** 일어나
  "요청이 서버에 닿지 못한" 상황으로 한정된다 → 낙관적 롤백의 의미가 명확해진다
- **영속화**: `localStorage`. 단계 이동 결과가 새로고침 후에도 유지된다
- **동시성**: 지원자마다 `version`을 두고, 이동 요청은 `expectedVersion`을 함께 보낸다.
  서버와 다르면 409(`ConflictError`)로 거부하고 **서버의 현재 상태를 함께 반환**한다
- **데이터**: 시드 고정 PRNG로 결정론적 생성. 같은 `seed`/`count`면 항상 같은 지원자가 나온다

### 검증용 URL 파라미터

15% 실패는 "때때로" 일어나서 에러 UI를 눈으로 확인하기 어렵다. 재현할 수 있게 열어 두었다.

| 파라미터 | 예 | 효과 |
| --- | --- | --- |
| `count` | `?count=1000` | 지원자 수 (기본 200, 최대 5000) |
| `count=0` | `?count=0` | 지원자 0건 — 빈 상태 확인 |
| `count=3` | `?count=3` | 일부 컬럼만 0건 — 컬럼 빈 상태 확인 |
| `fail` | `?fail=1` | 항상 실패 — 에러 화면 확인 |
| `fail=0` | `?fail=0` | 절대 실패하지 않음 |

개발 모드에서는 콘솔에 `__mockApi`가 노출된다. `?fail=1`은 초기 로드까지 실패시키므로,
**"목록은 정상 + 이동만 실패"** 를 만들려면 이쪽을 쓴다.

```js
__mockApi.configureMock({ failureRate: 1 })   // 이제부터 모든 요청 실패 → 롤백 확인
__mockApi.configureMock({ failureRate: 0 })   // 정상 복귀
```

## 키보드 조작

드래그앤드롭 대신 명시적 이동 메뉴를 쓰므로 **모든 조작이 키보드만으로 가능**하다.
화면에서는 헤더의 `키보드 조작` 버튼이나 `?` 키로 볼 수 있다.

| 키 | 동작 |
| --- | --- |
| `←` `→` | 이전 / 다음 단계 컬럼 (빈 컬럼은 건너뜀) |
| `↑` `↓` | 같은 컬럼 안에서 위 / 아래 카드 |
| `Home` `End` | 컬럼의 첫 / 마지막 카드 |
| `Enter` `Space` | 지원자 상세 패널 열기 |
| `M` | 단계 이동 메뉴 열기 |
| `↑` `↓` `Enter` | (메뉴에서) 단계 선택 |
| `Esc` | 메뉴 / 상세 패널 닫기 |
| `Ctrl` / `Cmd` + `Z` | 마지막 단계 이동 되돌리기 |
| `?` | 단축키 도움말 |

컬럼당 Tab 스톱은 하나다(roving tabindex). 1,000건에서도 Tab 몇 번이면 보드를 지나간다.

## 구현 범위

### 필수 요구사항

| # | 요구사항 | 상태 | 위치 |
| --- | --- | --- | --- |
| 1 | 보드 / 컬럼 / 카드 (이름·직무·지원일·단계) | 완료 | `features/board/` |
| 2 | 단계 이동 + mock API 저장 (새로고침 후 유지) | 완료 | `StageMoveMenu`, `mocks/api.ts` |
| 3 | 낙관적 업데이트 + 실패 시 원상 복구 + 피드백 | 완료 | `applicants/reducer.ts`, `ApplicantsProvider` |
| 4 | 이름 검색 + 직무 필터 (200건 이상 무지연) | 완료 | `features/filters/`, `board/selectors.ts` |
| 5 | 카드 클릭 시 상세 (사이드 패널) | 완료 | `features/detail/` |
| 6 | 로딩 / 에러 / 빈 상태 | 완료 | `BoardSkeleton`, `BoardError`, `EmptyState` |

빈 상태는 셋으로 나눴다 — 데이터 0건 / 특정 컬럼 0건 / 필터 결과 0건.

### 도전 요구사항

| 요구사항 | 상태 | 비고 |
| --- | --- | --- |
| 경쟁 상태 처리 | 완료 | 카드별 요청 큐 + 의도 병합 + 낡은 응답 차단 (`moveQueue.ts`) |
| 대량 데이터 성능 | 완료 | 컬럼별 가상 스크롤. 1,000건 DOM 노드 8,046 → 450 |
| 되돌리기 | 완료 | 진짜 API 호출. 실패도 처리 |
| 테스트 | 완료 | 94개 |
| 웹 접근성 | 완료 | 키보드 전용 조작, roving tabindex, live region, 포커스 트랩 |

못 끝낸 것과 의도적으로 범위 밖에 둔 것은 [DECISIONS.md](./DECISIONS.md#못-끝낸-것과-범위-밖으로-둔-것)에 적었다.

## 실측 수치

| 항목 | 값 |
| --- | --- |
| 1,000건 DOM 노드 | 450 (가상화 전 8,046) |

## 폴더 구조

```
src/
  domain/          단계 정의와 도메인 타입 (라벨·색·순서의 단일 출처)
  mocks/           자체 구현 mock 서버 (지연·실패·영속화·버전)
  features/
    applicants/    지원자 스토어: 리듀서, Provider, 이동 큐, 되돌리기
    board/         보드·컬럼·카드·이동 메뉴·셀렉터·키보드 내비게이션
    detail/        상세 사이드 패널
    filters/       검색/직무 필터
    feedback/      토스트(시각) / 스크린리더 안내(live region)
    selection/     상세 패널 선택 상태와 포커스 복귀
  components/      기능에 묶이지 않는 표현 컴포넌트
  lib/             날짜 포맷, 검색 정규화, 포커스 트랩
  test/            테스트 harness와 jsdom 셋업
```

기능 단위로 나눴다. 한 기능을 이해하려고 여러 폴더를 오갈 일이 없게 하려는 것이다.

## 진행 방식

기능 하나 = 커밋 하나 = `PROMPTS.md` 섹션 하나로 진행했다.
`git log --oneline`이 그대로 작업 순서이고, 각 커밋 메시지에 **무엇을·왜·AI 초안을 어떻게 손봤는지**가 들어 있다.

커밋 7은 테스트 2개가 **의도적으로 실패한 상태**로 들어가 있고, 커밋 11에서 통과한다.
시행착오 커밋(`fix(undo)`)도 되돌리지 않고 남겼다.
